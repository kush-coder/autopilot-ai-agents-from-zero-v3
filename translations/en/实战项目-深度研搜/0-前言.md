# Deep Research: Preface

---

Welcome to the "Deep Research" project, a hands-on project within the "AI Agent Practical Crash Course" that focuses more on multi-agent systems, long-running tasks, and engineering closure.

If you have already learned about LLM API calls, `Prompt`, `RAG`, `LangChain`, or `LangGraph`, the next step usually leads to a more practical question: **How exactly do you organize complex tasks into a project that can run, be observed, and be delivered?**

"Deep Research" is designed around this question. It is not another chat box, nor is it simply connecting a search `API`. Instead, it uses `DeepAgents` to build a conversational multi-agent research workstation: the user enters a research task or uploads an attachment, the main agent determines what information the task requires, then dispatches capabilities such as web search, database query, and the `RAGFlow` knowledge base, and finally organizes the answer, or generates `Markdown` / `PDF` files.

![Deep Research frontend home page: the left side shows WebSocket connection, assistant scheduling, and tool call statistics, and the middle provides task examples such as web search, database query, RAGFlow, uploaded file analysis, and report generation](../../../%E5%AE%9E%E6%88%98%E9%A1%B9%E7%9B%AE-%E6%B7%B1%E5%BA%A6%E7%A0%94%E6%90%9C/images/0/0-0-0-1.png)

**"Deep Research" is not simply an `Demo` that lets an LLM answer questions. It is an `DeepAgents` multi-agent hands-on project built around "main agent planning and scheduling, sub-agent division of labor, multi-source information retrieval, file generation and delivery, and real-time frontend-backend interaction."**

It may not yet be a complete enterprise-grade production system, but it is very suitable as a project-based course for the beginner-to-intermediate stage. Here you can systematically learn how a multi-agent application progresses step by step from concepts, examples, sub-agents, long-term memory, and middleware all the way to real `FastAPI` interfaces and frontend pages.

**Supporting source code repository**: https://github.com/didilili/deepsearch-agents

## 1. What does this project focus on learning

Many beginner projects only go as far as "the model can answer." That is certainly important, but there are still a few steps between that and a deliverable agent application.

In "Deep Research," the focus is not on making the model produce longer answers, but on solving more specific questions:

- When should a task search the web, when should it query the database, and when should it query the knowledge base;
- How should the sub-agents' `description`, `system_prompt`, and `tools` be divided;
- How uploaded files and generated files should be isolated by session to avoid tasks overwriting each other;
- Why long-running tasks cannot keep the `HTTP` request waiting forever, and why `WebSocket` should be used to report progress;
- How tools access the current `thread_id` and `session_dir` during deep nested calls;
- How the final result moves from command-line examples to frontend pages, output files, and download entry points.

Therefore, this project is more like an engineering exercise: starting from the basic capabilities of `DeepAgents`, it gradually connects sub-agents, memory, middleware, file tools, backend interfaces, and frontend integration.

After completing it, you should understand three things:

1. What kind of long-running tasks `DeepAgents` is suitable for, and how it differs from ordinary tool-based `Agent`.
2. How the main agent, sub-agents, tools, context, and file system should be layered.
3. How a multi-agent capability can actually be delivered through `FastAPI`, `WebSocket`, and frontend pages.

## 2. What will this project ultimately look like

From the user's perspective, it is a "deep research assistant."

Users can submit tasks such as:

```text
结合公开资料、数据库信息和我上传的文档，整理一份电商行业研究报告，并生成 PDF。
```

Behind the scenes, the system does the following as needed:

1. Determine which information sources the task requires;
2. Use `Tavily` to query public web information;
3. Use `MySQL` to query structured data;
4. Use `RAGFlow` to query the internal knowledge base;
5. Read the `PDF`, `Word`, `Excel`, or `Markdown` files uploaded by the user for this session;
6. Aggregate the materials and determine whether the information is sufficient;
7. Generate `Markdown`, and if necessary convert it to `PDF`;
8. Display the execution process, final result, and output files to the frontend.

![Deep Research system architecture diagram: the frontend connects to the backend through FastAPI and WebSocket, and the DeepAgents main agent schedules web search, database query, RAGFlow knowledge base, and file delivery tools](../../../%E5%AE%9E%E6%88%98%E9%A1%B9%E7%9B%AE-%E6%B7%B1%E5%BA%A6%E7%A0%94%E6%90%9C/images/0/0-2-0-1.svg)

During execution, the frontend does not simply show "waiting." It displays the `WebSocket` status, the number of assistant dispatches, the number of tool calls, and each `tool_start`, `assistant_call`, `task_result` event and others.

![Deep Research execution process page: the frontend displays web search tool calls, tool_start events, task_result events, and the answer organized by the main agent in real time](../../../%E5%AE%9E%E6%88%98%E9%A1%B9%E7%9B%AE-%E6%B7%B1%E5%BA%A6%E7%A0%94%E6%90%9C/images/0/0-2-0-2.png)

If the task generates files, the page also displays the output file list. In the example below, after the database query assistant executes `SQL`, the main agent continues by calling the `Markdown` document generation tool, and finally places the `.md` file into the output area of the current session so the user can download it directly.

![Deep Research file delivery page: after a database query task finishes, a Markdown file is generated, and the frontend displays the output file and download entry point](../../../%E5%AE%9E%E6%88%98%E9%A1%B9%E7%9B%AE-%E6%B7%B1%E5%BA%A6%E7%A0%94%E6%90%9C/images/0/0-2-0-3.png)

## 3. How the chapters are arranged

This project is divided into two parts.

The first part lays the foundation for `DeepAgents` capabilities, mainly corresponding to Chapters 1 through 7:

| Chapter    | Focus                                                          |
| ------- | ------------------------------------------------------------- |
| Chapter 1 | Establish the positioning of `DeepAgents`: long-running tasks, context, sub-agents, long-term memory  |
| Chapter 2 | Run through a minimal example and understand `invoke()`, `stream()`, and streaming `chunk`      |
| Chapter 3 | Learn dictionary-style sub-agents and how the main agent schedules them                  |
| Chapter 4 | Connect an existing `LangGraph` graph, or `LangChain`'s `Agent` or `Runnable` |
| Chapter 5 | Understand human-machine collaboration, interruption, approval, editing, and resuming execution                      |
| Chapter 6 | Understand `Backend`, the file system, `Store`, and long-term memory                  |
| Chapter 7 | Understand middleware and `Skills`, and add governance capabilities to the `Agent` execution chain          |

The second part is the main line of the "Deep Research" project, mainly corresponding to Chapters 8 through 14:

| Chapter     | Focus                                                                    |
| -------- | ----------------------------------------------------------------------- |
| Chapter 8  | Clarify the final project goals, overall architecture, and project directory                                    |
| Chapter 9  | Set up the foundations such as `.env`, `context.py`, `monitor.py`, `llm.py`, `prompts.yml` |
| Chapter 10 | Implement the web search sub-agent and connect `Tavily`                                     |
| Chapter 11 | Implement the database query sub-agent and connect `MySQL`                                    |
| Chapter 12 | Prepare the `RAGFlow` knowledge base and wrap the knowledge base assistant                                 |
| Chapter 13 | Assemble the main agent and integrate uploaded file reading, `Markdown` generation, and `PDF` conversion             |
| Chapter 14 | Use `FastAPI`, `WebSocket`, and the frontend pages to complete the full loop                            |

The advantage of this arrangement is that the core capabilities of `DeepAgents` are first broken down and explained separately, and later these capabilities are put back into a real project. You will not be overwhelmed by the complete project at the beginning, nor will you stop at scattered examples.

## 4. Technology stack and learning focus

The current project does not use many technologies, but each one has a clear role.

| Module       | Technology stack                                     | Role in the project                                              |
| ---------- | ------------------------------------------ | ----------------------------------------------------------- |
| Agent framework | `DeepAgents`                               | Create main and sub-agents and handle long-running tasks and division of labor                |
| Underlying runtime | `LangGraph`                                | Provide checkpoints, state recovery, and compatibility with graph workflows                  |
| Models and tools | `LangChain`                                | Provide model wrappers, tool declarations, and `Runnable` / `Agent` compatibility      |
| Web search   | `Tavily`                                   | Provide public information retrieval capability for the web search assistant                          |
| Structured data | `MySQL`                                    | Provide table names, sample data, and `SQL` query capability for the database query assistant         |
| Private knowledge base | `RAGFlow`                                  | Provide internal document Q&A capability for the knowledge base assistant                            |
| File delivery   | `Markdown` / `PDF` / `Word` / `Excel` parsing | Read uploaded attachments, generate `Markdown`, and convert to `PDF`               |
| Backend interfaces   | `FastAPI`                                  | Provide task start, cancellation, upload, file list, download, and `WebSocket` interfaces |
| Real-time communication   | `WebSocket`                                | Push execution progress, results, and exceptions to the frontend in real time                          |
| Frontend pages   | `React` + `Vite` + `Ant Design`            | Display sessions, task events, output files, and download entry points                      |
| Environment management   | `uv`                                       | Manage the `Python` environment and dependencies                                    |

You do not need to learn every technology in depth before starting. A better approach is to first understand what problem it solves in the pipeline, and then return to the corresponding chapter to look at the implementation details.

## 5. What this project deliberately does not cover

"Deep Research" is suitable for beginner-to-intermediate learning, but it is not a complete enterprise-grade production system.

The current version focuses mainly on the main pipeline:

```text
多智能体分工
  -> 多来源工具接入
  -> 会话上下文隔离
  -> 文件生成交付
  -> FastAPI 接口
  -> WebSocket 实时进度
  -> 前端闭环展示
```

Some production-grade capabilities are not expanded, such as:

- User login and data permissions;
- Multi-tenant isolation;
- Security scanning for uploaded files;
- Distributed task queues;
- Large-scale concurrency and rate limiting;
- Full event persistence;
- System evaluation and regression test suites;
- Monitoring, alerting, and tracing;
- Online report editing and collaboration.

All of these capabilities are important, but it is not appropriate to include them all at the beginning. In the first version, it is better to explain the main pipeline clearly first and then expand layer by layer later; this makes it easier to learn and easier to modify.

## 6. Project directory structure

The supporting source code repository is [deepsearch-agents](https://github.com/didilili/deepsearch-agents). The main structure of the final project is as follows:

```text
deepsearch-agents/
├── app/                         # 后端源码主目录
│   ├── agent/                   # 主智能体、模型配置、提示词加载和子智能体配置
│   │   ├── subagents/           # 网络搜索助手、数据库查询助手、RAGFlow 知识库助手
│   │   ├── llm.py               # 大模型初始化
│   │   ├── main_agent.py        # 主智能体组装与 run_deep_agent 执行入口
│   │   └── prompts.py           # 读取 prompts.yml 中的主智能体和子智能体配置
│   ├── api/                     # FastAPI 接口层、上下文和实时进度推送
│   │   ├── context.py           # ContextVar 保存 thread_id 和 session_dir
│   │   ├── monitor.py           # 统一封装工具调用、助手调用和任务结果事件
│   │   └── server.py            # 任务、取消、上传、文件列表、下载和 WebSocket 接口
│   ├── prompt/                  # prompts.yml，集中管理主智能体和子智能体提示词
│   ├── ragflow/                 # RAGFlow 连接配置和基础调用示例
│   ├── tools/                   # Tavily、MySQL、RAGFlow、文件读取、Markdown、PDF 工具
│   ├── utils/                   # 路径解析、Word/PDF 转换等通用工具
│   ├── output/                  # 每个会话生成的 Markdown、PDF 和输出文件
│   └── updated/                 # 用户上传文件的会话暂存目录
├── docker/                      # 本地 MySQL 等服务的 Docker Compose 配置
├── examples/                    # 1 到 15 章对应的 DeepAgents 示例脚本
├── frontend/                    # React + Vite 前端项目
├── tests/                       # 工具、连接管理、取消任务等测试
├── pyproject.toml               # Python 项目配置
├── requirements.txt             # 依赖清单
└── uv.lock                      # uv 锁定文件
```

## 7. Suggested learning approach

If this is your first encounter with `DeepAgents`, it is not recommended to start directly with the final main agent `main_agent.py`. It depends on sub-agents, checkpoints, `ContextVar`, `monitor`, file tools, asynchronous streaming execution, and `WebSocket` push.

A more stable order is:

```text
先看第 1 章，知道 DeepAgents 解决什么问题
  -> 跑第 2 章，熟悉 invoke / stream / chunk
  -> 看第 3 章，掌握子智能体配置和调度
  -> 看第 5 到 7 章，理解中断、记忆、中间件和 Skills
  -> 从第 8 章进入真实项目
  -> 第 9 章看懂 context、monitor、path_utils、llm、prompts
  -> 第 10 到 12 章完成三个专家助手
  -> 第 13 章组装主智能体和文件交付工具
  -> 第 14 章接上 FastAPI、WebSocket 和前端页面
```

The content that follows will systematically unpack the entire project along the main thread of **“DeepAgents core concepts -> Quick start and streaming analysis -> Sub-agents and compatible integrations -> Human-agent collaboration, memory, middleware -> Project engineering initialization -> Three expert assistants -> Main agent -> FastAPI and frontend closed loop”** .

After completing it, what you gain is not just “getting an AI Demo running,” but being able to clearly explain: why a `DeepAgents` multi-agent system should be designed this way, why the code should be split this way, and what problems `DeepAgents`, `WebSocket`, `Tavily`, `MySQL`, and `RAGFlow` respectively solve within a complete business chain.
