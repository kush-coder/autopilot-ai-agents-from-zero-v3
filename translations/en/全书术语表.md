# Book-Wide Glossary

This glossary is not meant to pile up jargon, but to help you connect the core concepts throughout this tutorial series.

When reading this tutorial, the places where you are most likely to get stuck are usually not "I have never seen this term before," but rather:

- You have seen Prompt, RAG, Tool, and Agent before, but cannot distinguish what problem each of them solves;
- Coze, Dify, LangChain, LangGraph, MCP, and DeepAgents all talk about "agents," but at different levels;
- You can run the code by following the cases, but cannot explain why a Workflow should be used here and an Agent should be used there;
- When working on real projects, `thread_id`, `session_dir`, Checkpoint, Backend, and ContextVar start to blur together again.

Therefore, this glossary is organized in a "from shallow to deep" manner: first establish a conceptual map, then look up terms by capability layer, and finally tie things together with comparisons of easily confused concepts.

---

## 1. How to Use This Glossary

If you are learning for the first time, it is recommended to read in this order:

1. First read Section 2, "Book-Wide Concept Map," to understand where each type of concept sits within the entire book.
2. Then read Section 3, "Quick Reference for High-Frequency Confusing Concepts," to first sort out the boundaries that are most easily confused.
3. When you reach a specific chapter, return to the corresponding group to look up terms; there is no need to memorize everything at once.
4. When working on projects, focus on "Engineering and Project Implementation Terms," as they are closer to real delivery.

Each term tries to answer three questions:

| Question              | What you should look at                |
| --------------------- | -------------------------------------- |
| What it is            | Look at the "One-sentence explanation" |
| What problem it solves| Look at "Problems solved"              |
| What it is confused with | Look at "Confusion points"          |
| Want to learn more    | Click "Suggested reading" to return to the original chapter |

## 2. Book-Wide Concept Map

You can first understand the entire course as eight layers of capability.

| Layer | What you are learning      | Representative terms                              | Core question                                  |
| ----- | -------------------------- | ------------------------------------------------- | ---------------------------------------------- |
| 1     | LLM fundamentals           | LLM, Token, Context Window, Inference, Hallucination | What the model is and where its capability boundaries are |
| 2     | Model communication methods| Prompt, Message, Output Parser, Structured Output | How to explain the task clearly and obtain the result |
| 3     | External knowledge supplementation | Embedding, Vector Database, Retriever, RAG, Rerank | How to retrieve content the model does not know |
| 4     | Tools and actions          | Tool, Function Calling, ToolMessage, Idempotency  | How the model calls external systems           |
| 5     | Flows and agents           | Workflow, Agent, ReAct, create_agent              | Who decides what to do next                    |
| 6     | Protocols and ecosystem integration | MCP, Resource, Server, A2A, Handoff      | How external capabilities and other agents are connected |
| 7     | Stateful orchestration     | LangGraph, State, Node, Edge, Checkpoint          | How complex flows can be controllable, recoverable, and observable |
| 8     | Enterprise-grade project engineering | FastAPI, SSE, WebSocket, ContextVar, Logging | How to build capabilities into a usable, traceable system |

A one-sentence memory aid:

> Prompt handles "how to ask," RAG handles "looking up materials," Tool handles "taking action," Workflow handles "fixed processes," Agent handles "dynamic decision-making," MCP handles "standardized capability integration," LangGraph handles "stateful process execution," and engineering handles "delivering it all stably."

## 3. Quick Reference for High-Frequency Confusing Concepts

| Concepts easily confused       | Quick distinction                                                            |
| ------------------------------ | ----------------------------------------------------------------------------- |
| Prompt vs System Message       | Prompt is the general term for input instructions; System Message is a system-level rule message with higher priority |
| RAG vs Fine-tuning             | RAG does not change model parameters and looks up materials at runtime; fine-tuning changes model behavior, format, and habits |
| Continued pre-training vs Fine-tuning | Continued pre-training leans more toward supplementing domain knowledge distribution; fine-tuning leans more toward task behavior and output style |
| Workflow vs Agent              | Workflow paths are mainly designed by humans; agents participate in deciding the next step |
| Tool Calling vs MCP            | Tool Calling is the model expressing an intent to call; MCP is a standardized protocol for integrating external capabilities |
| Tool vs Resource               | Tool is an executable action; Resource is more like readable context          |
| Agent vs Multi-agent           | Agent is a single decision-making system; multi-agent emphasizes collaboration and transfer of control among multiple agents |
| MCP vs A2A                     | MCP connects tools and resources; A2A connects another agent or agent system  |
| LangChain vs LangGraph         | LangChain leans toward component encapsulation; LangGraph leans toward stateful process orchestration |
| Conversation history vs Memory | Conversation history is message content; memory is the system's ability to use history |
| Checkpoint vs Store            | Checkpoint saves the state of a specific execution thread; Store leans more toward cross-thread long-term data |
| Backend vs Database            | Backend in DeepAgents is an abstraction for files, state, and storage, not equivalent to a business database |
| Subagent vs Skill              | Subagent is an assistant that can independently execute tasks; Skill is a reusable capability description and resource package |
| SSE vs WebSocket               | SSE mainly supports server-to-client one-way push; WebSocket supports bidirectional real-time communication |
| thread_id vs session_dir       | `thread_id` identifies the same execution thread; `session_dir` identifies the file directory for this task |

## 15. Most Easily Confused Concept Comparisons

### 15.1 RAG vs Fine-tuning vs Continued Pre-training

- **RAG**: Supplement external knowledge at runtime without changing model parameters.
- **Fine-tuning**: Change behavior, format, style, and task habits.
- **Continued pre-training**: Supplement deeper domain knowledge distribution, usually at higher cost.

One-sentence judgment: **When information is missing, think RAG first; when behavior is missing, look to fine-tuning; only when the underlying knowledge distribution itself is wrong should you consider continued pre-training.**

### 15.2 Workflow vs Agent

- **Workflow**: The process is designed by humans, and the model only completes sub-tasks at predetermined positions.
- **Agent**: The model participates in deciding what to do next.

One-sentence judgment: **When the path is fixed, prefer Workflow; when the path is open-ended, consider Agent.**

### 15.3 Tool / Function Calling vs MCP

- **Tool / Function Calling**: How the model expresses "I want to call this tool."
- **MCP**: How external capabilities are exposed in a standardized way.

One-sentence judgment: **One is more about the calling mechanism, and the other is more about the access protocol.**

### 15.4 MCP vs A2A

- **MCP**: Lets the model connect to external tools, resources, and prompt templates.
- **A2A**: Lets different Agents or Agent systems collaborate with each other.

One-sentence judgment: **One is about connecting capabilities, and the other is about connecting to another Agent.**

### 15.5 LangChain vs LangGraph

- **LangChain**: A packaging layer for components, models, Prompts, Parsers, Tools, and Agents.
- **LangGraph**: Graph-based orchestration, state flow, persistence, recovery, and observation layers.

One-sentence judgment: **LangChain is more like assembling capabilities, while LangGraph is more like running processes.**

### 15.6 Conversation History vs Memory vs Checkpoint

- **Conversation History**: The messages themselves.
- **Memory**: The system's ability to make use of history.
- **Checkpoint**: A state snapshot during a specific execution.

One-sentence judgment: **History is content, memory is capability, and checkpoint is a state-saving mechanism.**

### 15.7 Subagent vs Skill

- **Subagent**: An expert assistant that can be dispatched by the main agent.
- **Skill**: A reusable set of instructions, prompts, scripts, and resources.

One-sentence judgment: **A Subagent is more like a pair of hands, while a Skill is more like a toolkit.**

### 15.8 Backend vs Checkpointer vs Store

- **Backend**: A unified abstraction in DeepAgents for files, state, and long-term storage.
- **Checkpointer**: Saves execution state snapshots for recovery.
- **Store**: Saves long-term data across threads and sessions.

One-sentence judgment: **Backend is the abstraction layer, Checkpointer manages recovery, and Store manages long-term data.**

### 15.9 SSE vs WebSocket

- **SSE**: The server continuously pushes messages to the frontend, mainly received by the browser.
- **WebSocket**: The frontend and backend can communicate bidirectionally in real time.

One-sentence judgment: **If you only need server push, SSE is lighter; if you need bidirectional real-time interaction, WebSocket is more suitable.**
