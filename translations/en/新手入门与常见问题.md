# Getting Started and Common Questions

This document is the entry point for beginners in this repository. It not only tells you how to `pip install`, but more importantly helps you first figure out: what content this repository contains, where to start, which cases can be run directly, which projects require switching to companion source code repositories, and the order to follow when troubleshooting errors.

If this is your first time working with AI agent development, I recommend reading this document first. For the complete chapter structure, see the [Tutorial Table of Contents](%E6%95%99%E7%A8%8B%E7%9B%AE%E5%BD%95%E5%A4%A7%E7%BA%B2.md).

## 1. What is this project? What can I do with it?

This repository is the main tutorial repository for **"AI Agent Practical Crash Course: From Zero to Enterprise Deployment,"** with the goal of creating a set of Python agent learning materials that progress from simple to advanced, are easy to understand, include runnable code, support project-based learning, and help with interview review.

It currently contains five main categories of content:

| Content | Location | When to Read |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| Systematic tutorial main text | Markdown documents for chapters `1-1` through `26` in the root directory | When you want to systematically learn large language models, RAG, Agent, LangChain / LangGraph |
| Coze / Dify workflow cases | `案例与源码-1-Coze&Dify工作流智能体/` | When you want to quickly build demonstrable applications using low-code platforms |
| LangChain / LangGraph code examples | `案例与源码-2-LangChain框架/`, `案例与源码-3-LangGraph框架/` | When you want to directly run Python mini-cases in this repository |
| Enterprise-level project tutorials | `实战项目-电商问数/`, `实战项目-深度研搜/` | When you want to string together scattered knowledge points into complete projects |
| Navigation, terminology, interview, and resources | `教程目录大纲.md`, `章节索引与跳转指南.md`, `全书术语表.md`, `AI智能体与大模型应用开发面试题库.md`, `工具导航与参考资料索引.md` | When filling knowledge gaps, reviewing concepts, or preparing for interviews |

### 2.5 Learning by Time Budget

If time is tight, you can first arrange your schedule as follows:

| Time | Suggested Learning Approach |
| ---------------- | ----------------------------------------------------------------------------------------- |
| 7-day crash course | `1-1 -> 1-2 -> 9 -> 10 -> 11 -> 13 -> 14 -> 15 -> 17 -> 21 -> 22`, focus on getting the minimal code loop running |
| 15-day systematic introduction | First 3 days on foundational knowledge, 2 days experiencing Coze / Dify, 6 days mastering the LangChain main path, final 3 days moving into LangGraph |
| 90-day project / job search | Week 1 on fundamentals, Week 2 on LangChain / RAG / Agent, Week 3 on LangGraph, hands-on projects, and interview questions |

No matter which route you choose, the most important action remains the same: **After completing each chapter, run at least one example; after completing each phase, explain it in your own words.**

### 2.6 When Can You Move to the Next Phase

| Current Phase | Before Moving On, At Least Be Able To |
| -------------- | ------------------------------------------------------------------- |
| Foundational knowledge | Distinguish between Prompt, RAG, Agent, and fine-tuning without conflating them into one term |
| Low-code platforms | Independently build a simple Coze / Dify workflow and understand the boundary between platform drag-and-drop and code development |
| LangChain main path | Write `prompt -> model -> parser` and connect a Tool or a simple RAG |
| Agent phase | Explain the difference between "fixed workflow" and "model autonomous decision-making," and know when to use an Agent |
| LangGraph phase | Break a task down into State, Node, Edge instead of only writing linear scripts |
| Multi-agent phase | Judge when it's worth splitting into multiple Agents and when keeping a single Agent is more stable |

## 3. Environment Setup: Running Examples in This Repository

### 3.1 Python Version

The `requirements.txt` and `pyproject.toml` in the root directory already constrain the Python version:

| Project | Description |
| -------- | -------------------------- |
| Recommended version | Python 3.10 |
| Supported range | Python 3.10 to Python 3.13 |
| Not supported | Python 3.14 |

The reason is that the root directory examples depend on packages such as `langchain-redis`, which are not yet fully compatible with Python 3.14.

First check your local version:

```bash
python3 --version
```

If you have multiple Pythons on your computer, we recommend explicitly using `python3.10`.

### 3.2 Create a Virtual Environment

Run this in the project root directory — the level where you can see `README.md`, `requirements.txt`, and `.env-example`. Open a terminal and execute:

macOS / Linux:

```bash
# 创建虚拟环境（会多出一个 .venv 文件夹）；推荐使用 Python 3.10
python3.10 -m venv .venv
# 激活虚拟环境
# Windows（CMD）：
.venv\Scripts\activate
# Windows（PowerShell）：
.venv\Scripts\Activate.ps1
# macOS / Linux：
source .venv/bin/activate
```

After successful activation, you will usually see `(.venv)` at the beginning of your terminal prompt.

### 3.3 Install Dependencies

Still in the **project root directory** and with the virtual environment activated, run:

```bash
pip install -r requirements.txt
```

If the network is slow, you can switch to the Tsinghua mirror in China:

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

`requirements.txt` covers the main dependencies for the ordinary examples in the root directory. Practical projects such as Shopkeeper Data Q&A have their own environment instructions; see Section 6 of this document.

## 4. Configure API Keys and .env

### 4.1 Copy .env-example

In the project root directory, run:

```bash
cp .env-example .env
```

Windows users can also manually copy `.env-example` and then rename it to `.env`.

After opening `.env`, replace the placeholder keys with real keys. Do not commit real API keys to Git; this repository already ignores `.env` via `.gitignore`.

### 4.2 Common Environment Variables

Different chapters read different variable names. Common variables are as follows:

| Variable Name | Purpose |
| -------------- | ---------------------------------------------------------- |
| `QWEN_API_KEY` | Used in early HelloWorld examples to call Qwen |
| `aliQwen-api` | Used in most LangChain / LangGraph examples to call Alibaba Bailian / Qwen |
| `deepseek-api` | DeepSeek-related examples |

A relatively complete `.env` example:

```env
QWEN_API_KEY='sk-你的通义千问Key'
aliQwen-api='sk-你的阿里云百炼Key'
deepseek-api='sk-你的DeepSeekKey'

# 天气工具示例
OPENWEATHER_API_KEY='你的OpenWeatherKey'
```

The most error-prone part here is the variable name. `aliQwen-api`, `deepseek-api`, and `tavily_api_key` must exactly match the `os.getenv("...")` in the code, including casing, hyphens, and underscores.

> **Note:** The variable names in the table above are conventions used by this repository's code, not mandatory environment variable names required by the respective vendors. Official platforms typically only require you to have a valid API key; when placing it in `.env`, the variable name must match the name read by the local example code.

### 4.3 Where to Apply for API Keys

The following describes how to obtain API keys by **platform**, for use in filling in `.env`.

#### Qwen / Alibaba Bailian

- **Purpose**: A large number of examples in this repository use `aliQwen-api` or `QWEN_API_KEY` to call Qwen.
- **Application steps**: The tutorial has illustrated instructions; you can directly view the "**2. Large model service platforms**" section in [Chapter 10 - LangChain Quick Start and HelloWorld](10-LangChain%E5%BF%AB%E9%80%9F%E4%B8%8A%E6%89%8B%E4%B8%8EHelloWorld.md) (including the Alibaba Bailian platform and the API-Key management entry table) and the "**4. Hands-on: HelloWorld based on Alibaba Bailian**" section (including the API key acquisition, model name, and Base URL trio). The brief steps are as follows:
  1. Open the [Alibaba Cloud official website](https://www.aliyun.com/) and log in; if you do not have an account, you need to register first.
  2. Search for "**Bailian**" or go to the product page related to "**Lingji Model Service**" (the specific name may vary depending on Alibaba Cloud's current product).
  3. After enabling "Model Service" or "Bailian," find **API-KEY** management in the console and create or copy a key.
  4. The key is generally a long string starting with `sk-`; copy it into `aliQwen-api` or `QWEN_API_KEY` in `.env`.

#### DeepSeek

- **Purpose**: DeepSeek examples under `02-models_io` in this repository, as well as some scripts that use `deepseek-api`.
- **Application steps**: The tutorial has screenshots and steps; see [Chapter 10 - LangChain Quick Start and HelloWorld](10-LangChain%E5%BF%AB%E9%80%9F%E4%B8%8A%E6%89%8B%E4%B8%8EHelloWorld.md) (including DeepSeek API key acquisition and configuration in the "Multi-model coexistence" section). The brief steps are as follows:
  1. Open the [DeepSeek Open Platform](https://platform.deepseek.com/) (or search for "DeepSeek API").
  2. After registering/logging in, create a key in the console or on the "API Key" page.
  3. Fill the key (generally starting with `sk-`) into `deepseek-api` in `.env`.

#### OpenAI-compatible interfaces

- If an example uses the `openai` library with the `base_url` method (for example, connecting to DeepSeek or domestic OpenAI-compatible vendors), you usually only need to configure the corresponding vendor's key and the `base_url` from the documentation in `.env`. For **connection methods and parameter explanations**, see "3.1 Using OpenAI-compatible interfaces" and "3.3 Connecting to Qwen (Alibaba Bailian)" in [Chapter 11 - Model I/O and Model Integration](11-Model-I-O%E4%B8%8E%E6%A8%A1%E5%9E%8B%E6%8E%A5%E5%85%A5.md).
- **Official OpenAI**: You need to register and create an API key on the [OpenAI platform](https://platform.openai.com/), and you must be able to access its services (a proxy may be required in some regions).

## 5. Quick Reference for Common Issues

### 5.1 Dependency-Related Issues

| Problem | Common Cause | Solution |
| -------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------- |
| `ModuleNotFoundError: No module named 'xxx'` | Dependencies not installed, or the `.venv` is not activated | After activating the virtual environment, run `pip install -r requirements.txt` in the project root directory |
| Error during installation: `requires-python <3.14`             | Python version is too high              | For regular examples in the root directory, switch to Python 3.10~3.13, 3.10 recommended                            |
| RAG, Memory, Redis examples do not run                | Depend on external services or system packages         | Run HelloWorld first, then prepare Redis, Redis Stack, PDF / Word parsing dependencies according to the corresponding chapters |

Check the current Python version:

macOS / Linux:

```bash
python --version
which python
pip show langchain
```

Windows:

```bat
python --version
where python
pip show langchain
```

### 5.2 API Keys and .env

| Problem                   | Common cause                                                         | Solution                                                                 |
| ---------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 401, 403, invalid API key | Incorrect key, insufficient platform quota, service not enabled                               | Go back to the platform console and check the key, quota, and model service status                                 |
| `os.getenv()` reads an empty value | `.env` does not exist, variable names are inconsistent, or the IDE / debugger working directory is misconfigured | Confirm that `.env` exists in the root directory and that variable names match the code; check the working directory again when using an IDE / debugger |

When troubleshooting `.env`, do not post the real key in issues, chat windows, or screenshots. Just state which variable names you have configured.

### 5.3 Working Directory and Encoding

| Problem                            | Common cause                                                    | Solution                                                                                   |
| ------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Cannot find `.env`                   | `.env` does not exist, or the IDE / REPL / debugger working directory is not set to the repository | Confirm that `.env` already exists in the root directory; adjust the working directory if necessary, or explicitly pass the `.env` path in code                  |
| `UnicodeDecodeError` or garbled Chinese text | Files are not UTF-8 encoded                                         | Use VS Code / Cursor to save `.env` and `.py` as UTF-8                                          |
| Relative paths cannot find files              | Custom code directly uses relative paths based on the current working directory              | The examples in this repository locate resources by script directory; custom paths are recommended to use absolute paths or be constructed via `Path(__file__)` |

### 5.4 Ollama Examples

Ollama does not require a cloud API key, but it does require installing and starting Ollama locally, as well as pulling the model in advance.

```bash
ollama --version
ollama list
ollama run qwen:4b
```

`qwen:4b` is the lightweight model tag used in the beginner examples of this repository. Ollama models and tags are continuously updated; for actual available names, refer to the current [Ollama model library](https://ollama.com/search) page.

After confirming that the model runs normally from the command line, run the LangChain examples under the `03-ollama` directory.

### 5.5 Black Formatting

This repository uses Black to standardize Python code style.

```bash
black --check .
black .
```

If you use VS Code / Cursor, you can install Microsoft's `Black Formatter` extension and enable format-on-save.

## 6. How to Ask Questions When You Encounter Problems

If you get stuck, you can troubleshoot on your own in the following order:

1. Is the current directory the project root?
2. Has the virtual environment been activated?
3. Is Python between 3.10 and 3.13?
4. Have you run `pip install -r requirements.txt`?
5. Is there a `.env` file in the root directory?
6. Are the `.env` variable names consistent with the code?
7. Does this example depend on external services such as Redis, Ollama, Docker, Qdrant, or Elasticsearch?
8. Have you mixed together environments from regular examples in the root directory and practical projects such as Shopkeeper Data Q&A?

If the problem is still unresolved, try to include the following information when opening an issue:

```text
1. 你运行的命令
2. 完整报错信息
3. Python 版本
4. 操作系统
5. 你运行的是哪个章节或哪个脚本
6. 是否配置了 .env，以及配置了哪些变量名（不要贴真实 Key）
```

This way others do not have to guess your environment, making it easier to help locate the problem.
