### Technical Highlights

- **Dual workflows**: **excel_preprocess** converts Excel into a message list; **message_process** first calls excel_preprocess to obtain `msg_list`, then analyzes each message and outputs a report array. The UI uploads files and invokes message_process through Coze UI components.
- **Excel preprocessing**: The Excel received by the Start node is converted to an online file URL, and readExcel reads it as JSON; a code node escapes `output` (e.g., `\"` → `"`) before parsing, extracts columns by `msg_column_name` and `msg_id_name`, and outputs `msg_list` (each item containing id and msg).
- **Batch processing pipeline**: For each `{id, msg}`, execute in sequence — code parses the current item → LLM "Question Classification" (product/content/experience, etc. labels) → LLM "Content Summary" (within 30 characters) → LLM "Sentiment Analysis" (rank + reason) → Code_1 wraps it into a unified output structure; the batch processing output is the analysis result array.
- **Output and UI**: The final output of message_process includes summary, product, content, experience, rank, reason, msg_id, msg, etc. for each conversation, for frontend display; the interface is drawn using the Coze UI and passes parameters through FileUpload, Textarea, etc. to trigger the workflow.

- `msg_column_name` and `msg_id_name`: These are input parameters of the "Start" node and the code node, used to adapt to Excel files with different formats. The table read by readExcel is a JSON array of "row → object" where each row object has multiple columns (keys are the headers). `msg_column_name` specifies which column name corresponds to the "customer service conversation content" (for example, in this case, the Excel header is `history_message`, so fill in `history_message`); `msg_id_name` specifies which column name corresponds to "the number/ID of each conversation" (for example, in this case, the header is `msg_id`, so fill in `msg_id`). The code node uses these two parameters to extract the corresponding columns from each row and assemble `msg` and `id` in `msg_list`. This way, when using Excel files with different headers, you only need to change these two parameters to reuse the workflow.

### Workflow Overview

**excel_preprocess:**

```
开始(excel, msg_column_name, msg_id_name)
    ↓
readExcel(url) → output（JSON 字符串）
    ↓
代码：转义 + 提取列 → msg_list[{ id, msg }, …]
    ↓
结束：输出 msg_list
```

**message_process:**

```
开始(excel, msg_column_name, msg_id_name)
    ↓
调用工作流 excel_preprocess → msg_list
    ↓
批处理：对 msg_list 中每条
    ├─ 代码：解析当前条 id、msg
    ├─ 大模型：问题分类 → product、content、experience
    ├─ 大模型：内容总结 → summary（30 字内）
    ├─ 大模型：情感分析 → rank、reason
    └─ 代码_1：封装为单条 output
    ↓
结束：输出分析结果数组（报告列表）
```

## 1. Overall Architecture

The business logic of this project is implemented by two workflows: excel_preprocess and message_process.

Our provided customer service conversation log file format is Excel. It is first processed by excel_preprocess into a message list, and then message_process extracts information from the message list and generates an analysis report.

This project uses components provided by the Coze platform **UI** to draw the application's interface.

###### The code content is as follows

```python
import json
def extract_column(data_str: str, column: str) -> list:
    """
    从 data["output"] 字段解析 JSON 列表，并提取指定列值列表
    :param data: 原始输入(dict)
    :param column: 要提取的列名(String)
    :return: 包含所有列值的 list
    """
    # 1) 去掉转义
    data_str = data_str.replace('\\\"', '"')

    rows = json.loads(data_str)

    # 提取列
    result = [row.get(column) for row in rows]
    return result

async def main(args: Args) -> Output:
    params = args.params
    input = params["input"]
    msg_column_name = params["msg_column_name"]
    msg_id_name = params["msg_id_name"]

    msg_list = extract_column(input, msg_column_name)
    msg_id_list = extract_column(input, msg_id_name)
    msg_list = [{"id": msg_id_list[i], "msg": msg} for i, msg in enumerate(msg_list)]

    # 构建输出对象
    ret: Output = {
        "msg_list": msg_list
    }
    return ret
```
