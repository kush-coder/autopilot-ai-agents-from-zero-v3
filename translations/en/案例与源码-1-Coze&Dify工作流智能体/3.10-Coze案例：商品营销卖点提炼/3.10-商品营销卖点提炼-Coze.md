# 3.10 - Coze Case Study: Product Marketing Selling Point Extraction

---

## Case Study Overview

This case study is the **most structurally complex** example in the Coze tutorial: it adopts a hybrid architecture of **1 Agent + 5 workflows** to implement a complete marketing chain from "setting product information" → "extracting selling points" → "converting selling points to buying points" → "generating Xiaohongshu copy / short video scripts," and supports executing any individual step on demand.

### Platform Capabilities Used (No External Plugins)

| Capability/Node Type       | Description                                                                                                                                    |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **Start / End**            | Workflow entry and exit points; the start node can receive `BOT_USER_INPUT` and parameters with the same names as data table fields (such as `name`, `description`), making it easy for the Agent to supplement input parameters from conversations or the database. |
| **Output**                 | Outputs prompts/results to the user one by one or all at once; the streaming toggle controls the output method.                                 |
| **Q&A**                    | Core of multi-turn interaction: supports "direct answer" (encapsulated as `USER_RESPONSE`) or "option answer" (different branches based on options, equivalent to branching + intent recognition). |
| **Variable Assignment**    | Writes node results into **user variables** (product name, product features, three types of selling points, three types of buying points, etc.) for reuse by this workflow, subsequent workflows, and the main process. |
| **Code**                   | Python: validates product name length (≤9 characters), randomly selects "marketing keywords / short video opening and closing technique keywords," etc., for validation and generation diversity. |
| **Large Model**            | Generates one-sentence product descriptions, general/unique/guarantee selling points, selling point → buying point conversion, Xiaohongshu copy, short video storyboard scripts; relies on system prompts to constrain format and style. |
| **Selector**               | Performs conditional branching based on code or previous node output (such as whether hot topics were retrieved or whether the name is valid). |
| **Loop / Terminate Loop**  | Within an infinite loop, implements "re-ask if validation fails" or "generate copy/scripts for multiple rounds until the user chooses to stop generating." |
| **Text Processing**        | String concatenation and templates, such as supplementary description concatenation and final aggregation of selling points/buying points/copy/scripts into a single Markdown document. |
| **Data Table + SQL**       | Table `product_list` persists product names and descriptions; SQL custom node writes data; when there is no product information in the conversation, the Agent can retrieve the latest record from this table to fill workflow input parameters. |
| **Knowledge Base Retrieval** | Knowledge bases "Shangguigu-Douyin Hot Topics," "Shangguigu-Weibo Hot Topics," "Short Video Script Techniques_Opening/Closing," and "High-Quality Marketing Copy Techniques" provide hot topic and technique context for copy/script generation. |
| **Workflow Sub-calls**     | The main process sequentially calls 4 sub-workflows; the Agent can also call any one of them individually based on user intent. |

### Five Workflow Responsibilities

| Workflow Name                | Responsibility Summary                                                                                                                                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **set_product_name_and_desc** | Sets/updates product information: guides input or selection of sample product names → length validation (loop + code + selector) → large model generates description → if satisfied, writes to user variables, otherwise concatenates supplementary input and writes → writes to data table → outputs organized product information. |
| **selling_point_generation**  | Generates three types of selling points: general / unique / guarantee. Each type follows "prompt → multi-turn Q&A (can be AI-answered) → large model generation → satisfied/revise branch → write to corresponding user variable." Relies on product name and product features in user variables. |
| **selling2buying_point**      | Converts existing three types of selling points into three types of buying points (pain points, delight points, itch points, excitement points, safety points, etc.). Each type follows "prompt → large model conversion → satisfied/supplement branch → write to corresponding user variable." Inputs come from user variables; no additional parameters needed. |
| **red_book_and_video_script** | Based on buying points in user variables, generates "Xiaohongshu copy" or "short video storyboard scripts" for multiple rounds. Within the loop: whether to generate → hot topic retrieval (knowledge base) → whether to use hot topic → random technique keywords (code) → technique retrieval → large model generation → output; supports multiple rounds until the user chooses to stop generating. |
| **Main Process (Full Flow)**  | Start → set_product_name_and_desc → selling_point_generation → selling2buying_point → red_book_and_video_script → text processing (aggregate product + selling points + buying points + copy + scripts) → End. |

### Technical Highlights

- **Agent scheduling**: Uses natural language conditions in the "persona and reply logic" (such as "only ask to set product information," "only ask to generate selling points," "only ask to convert selling points to buying points," "generate copy or scripts") to decide which workflow to call; when running the full flow at once, the above 4 sub-workflows are called in a fixed order.
- **User variables span multiple turns and workflows**: Product name, product features, general/unique/guarantee selling points, general/unique/guarantee buying points, etc. are all stored as user variables. Sub-workflows obtain inputs through start nodes or by directly referencing user variables, achieving "set once, use everywhere."
- **Q&A node branching**: Extensively uses "option answers" (such as satisfied / revise, A/B/other), with the model determining user intent and entering different branches, achieving "if satisfied, store to database/write variables; otherwise continue asking or call the large model to supplement."
- **Loop + selector + code**: Product name length validation uses "infinite loop + code to calculate length + selector judgment + terminate loop/re-ask"; copy/script generation uses "Q&A within the loop to ask whether to continue + selector to distinguish Xiaohongshu/short video + code random keywords + knowledge base retrieval + large model."
- **Data table and parameter supplementation**: `product_list` has the same parameter names as the start node (`name`, `description`), making it easy for the Agent to retrieve the latest record from the database when there is no product information in the conversation and fill it into the workflow, ensuring scenarios such as "generate selling points alone" are usable.
- **Knowledge base and random techniques**: Hot topic libraries, copy technique libraries, and short video opening/closing technique libraries inject context into the large model through retrieval; the code node randomly selects keywords (such as "describe appearance," "highlight price," etc.) and then retrieves, making the angle of each generated copy/script different.
- **Structured output and format constraints**: The large model constrains output format through system prompts (such as selling point/buying point lists, Xiaohongshu title/body/tags, short video storyboard duration/visuals/dialogue, etc.), facilitating subsequent display and concatenation.

### Workflow Overview

**Full flow (complete at once: set product → selling points → buying points → copy/scripts):**

```
开始(BOT_USER_INPUT)
    ↓
set_product_name_and_desc → 用户变量：产品名称、产品功能；数据表 product_list 写入
    ↓
selling_point_generation(name, description) → 用户变量：通用/独特/保障性卖点
    ↓
selling2buying_point → 用户变量：通用/独特/保障性买点
    ↓
red_book_and_video_script → 循环内可多轮生成；输出 red_book_output、script_output（列表）
    ↓
文本处理：拼接 产品名称 + 三类卖点 + 三类买点 + 小红书文案列表 + 短视频脚本列表 → 汇总 Markdown
    ↓
结束：返回汇总结果
```

**Set product information alone:** Start → set_product_name_and_desc → End.

**Generate selling points alone:** Start → selling_point_generation (inputs from user variables or database name/description) → End.

**Convert selling points to buying points alone:** Start → selling2buying_point → End.

**Generate copy or scripts alone:** Start → red_book_and_video_script (multi-round loop) → End.

###### 1. Assign ifshort Based on Name Length

This is a code node.

![1. Assign ifshort Based on Name Length](../../../../images/3.10/3.10-3-1-29.png)

The code is as follows:

```python
# 在这里，您可以通过 'args'  获取节点中的输入变量，并通过 'ret' 输出结果
# 'args' 已经被正确地注入到环境中
# 下面是一个示例，首先获取节点的全部输入参数params，其次获取其中参数名为'input'的值：
# params = args.params;
# input = params['input'];
# 下面是一个示例，输出一个包含多种数据类型的 'ret' 对象：
# ret: Output =  { "name": '小明', "hobbies": ["看书", "旅游"] };

async def main(args: Args) -> Output:
    params = args.params
    ifshort = len(params["input"]) <= 9
    # 构建输出对象
    ret: Output = {
        "ifshort": ifshort
    }

    return ret
```
