# 3.3 - Coze Case Study: Product Marketing Poster Generation

## Case Study Overview

### Plugins / Nodes Used

| Type | Name / Capability | Purpose |
| ------------ | ------------------- | ---------------------------------------------------------------------------------------- |
| **Image Generation** | Image Processing → Image Generation | Performs **text-to-image** generation based on prompts, supports different aspect ratios (such as 2:3); routes to the corresponding ratio and model based on the proportion branch. |
| **Instruction Editing** | Instruction Editing Plugin | **Image editing**: edits the user-uploaded original image based on prompts. |
| **Quality Enhancement** | Quality Enhancement Plugin | **Sharpening**: enhances the clarity of the user-uploaded image (no prompt required). |
| **Image Overlay** | Image Overlay Plugin | Overlays a QR code or logo onto the base image, with position parameters (such as qr_place) specifying relative placement and scaling ratio. |

### Technical Highlights

- **Dual workflows**: This case includes **img_generate** (generate/export poster) and **read_history** (query historical records); the interface implements the "Generate" and "History" capabilities by calling these two workflows.
- **Generation / export routing**: Based on whether `logo_place` is empty, it distinguishes between the **generation path** and the **export path**; the generation path produces the poster image, while the export path adds a QR code and logo to an existing image.
- **Generation path branches**: When `img` is empty, it is **text-to-image**, routed to image generation nodes with different aspect ratios according to `proportion`; when `img` is not empty, it is **image editing** or **sharpening** (distinguished by whether the prompt is empty).
- **Export path**: First, based on whether `qr_img` is empty, it decides whether to use the user's QR code or the official QR code, and uses the image overlay plugin to overlay it onto the base image; then it adds a logo using the image overlay plugin in the same way; the two branches are merged into a unified output through **variable aggregation**.
- **Persistence**: The generated/exported images and prompts are written into the data table **Generation**; read_history queries records from this table and returns a list for interface display.

### Workflow Overview

**img_generate：**

```
开始(logo_place, img, proportion, prompt, qr_img, qr_place, …)
    ↓
分支：logo_place 是否为空？
    ├─ 为空 → 生图链路
    │     ├─ img 为空 → 文生图：按 proportion 分支 → 图像生成(提示词) → 海报图
    │     └─ img 不为空 → 改图 / 变清晰（指令编辑 或 画质提升）→ 海报图
    └─ 不为空 → 导出链路
          ├─ 按 qr_img 添加二维码（用户二维码或官方二维码）→ 叠图
          └─ 添加 logo → 叠图
    ↓
变量聚合 → 写入 Generation 表 → 结束：输出 output（图片）
```

**read_history：** Start → Database query of the Generation table → End: Returns outputList (historical record list).

##### 2.2 Export Path

###### 2.2.1 Add QR Code

**Determines whether the user has uploaded a QR code based on whether the qr_img parameter is empty.**

![Product marketing poster generation case operation screenshot](../../../../images/3.3/3.3-4-1-13.png)

① If the user has uploaded a QR code

② If the user has not uploaded a QR code

![Product marketing poster generation case operation screenshot](../../../../images/3.3/3.3-4-1-17.png)

The official QR code image has a fixed size, so it is directly scaled at the specified 30% ratio.

**Variable Aggregation**

The data from the two branches is aggregated together through a variable aggregation node, and downstream only needs to process the same variable output.

![Product marketing poster generation case operation screenshot](../../../../images/3.3/3.3-4-1-18.png)

Only one of the multiple branches' data exists, so they are directly concatenated together. The final effect is that whichever branch is executed, that branch's output becomes the output after variable aggregation.

#### 4.1.3 Variable Aggregation

Regardless of whether upstream is the export path or the generation path, the final output is an image, which is aggregated together as output and passed downstream.

![Product marketing poster generation case operation screenshot](../../../../images/3.3/3.3-4-1-20.png)

![Product marketing poster generation case operation screenshot](../../../../images/3.3/3.3-4-1-21.png)

Stores the generated image and prompt into the data table Generation. This node outputs the written row number and the current data list in the data table to downstream. The data output in the current path is not used.

#### 4.1.5 End
